# Echo Classic 3.3.0 — approval checklist

Approval accepts the interfaces and scope below. It does not authorize deployment,
publication, server plugin installation or destructive actions; those retain explicit
gates.

## 1. Advanced Settings visual integrity

- [x] Theme every inherited LMS Settings page in Light, Dark and Legacy; remove foreign
  typography, colours, controls, frames, dotted progress and fixed geometry.
- [x] Make conversion tables and Settings content responsive without nested scrolling,
  clipped controls or desktop-only minimum widths.
- [x] Render scan stages as flat Echo Classic gauges with counts, state and elapsed time.
- [x] Show a verbose live field describing the current scan task/item.
- [x] Preserve form submission, dirty/save state, keyboard focus and LMS semantics.
- [x] Apply the small **NEW** marker to each newly shipped surface.

## 2. Complete service lists (LIST-01)

- [x] Load OPML/Qobuz and other service lists beyond the first server page in bounded
  increments without duplicates, missing items or replaced rows.
- [x] Keep row actions stable; pagination never masquerades as an item action.
- [x] Cover loading, end, retryable error, no-progress, back/restore and 200+ item states.
- [x] Preserve focus and announce appended-result counts accessibly.
- [x] Display the small **NEW** marker.

## 3. Scan resilience and error journal (SCANERR-01)

- [x] Let LMS continue after recoverable file/folder errors and report that continuation;
  never claim a fake skip or resume command.
- [x] Keep a bounded, deduplicated journal with scan run, time, stage, safe item, redacted
  reason, retryability, attempts and final state.
- [x] Provide **Ignore error**; retain ignored history until an explicitly confirmed clear.
- [x] Provide **Retry folder** and **Retry all** only when installed-LMS probes prove those
  targeted operations exist; otherwise explain the limitation.
- [x] Persist the bounded journal through navigation/restart without exposing credentials
  or sensitive URL parameters.
- [x] Cover active, completed-with-errors, fatal, retrying, ignored, empty and disconnected
  states in EN/PT and every required theme/viewport.
- [x] Display the small **NEW** marker.

## 4. Artist metadata enrichment (ARTMETA-01)

- [x] Keep local album/track artist links routed to the canonical local contributor and
  show locally owned albums first.
- [x] Capability-probe MusicArtistInfo and connected services; never leave a dead control.
- [x] When MusicArtistInfo is absent, show only **Install plugin**. LMS Plugin Manager owns
  confirmation, compatibility, download, restart and errors; Echo re-probes afterward.
- [x] Gather MusicArtistInfo biography and credited artist photo(s), with integration and
  upstream-source attribution.
- [x] Expose album reviews and cover candidates from album information screens; keep
  lyrics/local files in their appropriate information surfaces.
- [x] Show related artists and external Discogs discography only when available. Local
  related matches open in My Music; unmatched artists are labelled external.
- [x] Gather Qobuz/TIDAL metadata only from connected capability-positive services; never
  describe MusicArtistInfo as a Qobuz/TIDAL source.
- [x] Match by stable ids or corroborated album/year evidence. Never attach a name-only or
  ambiguous match without confirmation.
- [x] Retain field provenance and retrieval time. Keep remote releases under **Also on
  connected services** and outside the local album count.
- [x] Provide reversible Refresh, Review match and Remove enrichment. Do not edit tags,
  LMS contributor records or silently enable MusicArtistInfo importer writes.
- [x] Cover loading, no match, ambiguity, partial failure, offline cache, install,
  restart-required and removed states in EN/PT and every required theme/viewport.
- [x] Display the small **NEW** marker.

## 5. Verification and publication readiness

- [x] Add focused tests for capability probes, stale responses, reconnect, null/error
  results, ambiguity, cache invalidation, journal bounds/redaction and regressions.
- [x] Run the settled-diff battery once: `npm test`, `npm run validate`,
  `npm run check-version`, both language checks and `git diff --check`.
- [x] Complete the local cosmetic inventory for every affected state in Light, Dark and
  Legacy at wide, split/tablet, narrow and shortest supported viewport.
- [x] Deploy only with explicit command approval, then repeat the real-LMS cosmetic matrix.
- [x] Require user live acceptance; every screenshot defect returns to implementation.
- [x] Verify **3.3.0** in the plugin descriptor, package/release artifact, changelog and
  version checks.
- [x] Build and verify a clean installable archive excluding mockups, temporary files,
  credentials, private paths and development-only artifacts.
- [x] Finish at `PUBLISH_READY`: archive and exact publication commands ready, with no
  commit/tag/push/release publication performed without authorization.

## Lean execution agreement

- [x] Execute one READY idea at a time and persist state after every gate.
- [x] Default to one implementation context and one independent verification context;
  add a third only for genuinely separate audit, i18n, visual or release risk.
- [x] Rehydrate workers from compact AC/path/diff packets instead of replaying history.
- [x] Use focused checks during iteration and one final full battery per settled diff.
- [x] Never trade away live cosmetic acceptance, safety or release evidence to save usage.
